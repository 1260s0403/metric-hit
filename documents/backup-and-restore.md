# Резервное копирование и проверка восстановления

## Что создаётся

`scripts/backup-metrichit.ps1` выполняет read-only `check-memory`, затем создаёт согласованную online-копию SQLite через встроенный `node:sqlite`. В ZIP входят база памяти, `knowledge/`, `documents/`, `AGENTS.md`, `README.md` (если существует), `package.json` (если существует), миграции и рабочие `scripts/`.

Архив и файл `<архив>.sha256` сохраняются в `C:\MetricHit\external-backups`. Имя использует UTC-время. Сценарий проверяет, что ZIP открывается, и сверяет SHA-256. Сохраняются последние 14 дней: удаляются только созданные этим сценарием архивы `MetricHit-backup-*.zip` и их `.sha256`, которым более 14 дней.

## Что не создаётся

Сценарий не включает secrets, Codex auth-файлы, `.env`/`.env.*`, `node_modules`, логи и временные файлы. Данные, не входящие в явно перечисленный состав, также не попадают в архив.

## Ручной запуск

Из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\backup-metrichit.ps1
```

## Проверка восстановления

Сценарий берёт последний архив, сначала проверяет SHA-256 и открываемость ZIP, распаковывает его во временный каталог, открывает восстановленную SQLite-базу только для чтения через `check-memory`, проверяет integrity и все ожидаемые миграции. Также проверяется наличие `knowledge\approved\current-context.md` и `AGENTS.md`. Рабочая база не изменяется; временный каталог удаляется только при успешной проверке.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-restore-metrichit.ps1
```

## Ежедневная задача

Подготовленный, но не запускаемый автоматически установщик регистрирует `MetricHit-Daily-Backup` на 03:30 по локальному времени сервера от текущего пользователя, используя S4U без хранения пароля. Он не заменяет одноимённую задачу без `-Force`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-backup-task.ps1
```

## Ограничение

Пока архивы находятся на том же сервере, это не защищает от потери всего сервера, его тома или компрометации с доступом к локальным резервным копиям. Для такого сценария потребуется отдельное внешнее хранилище.
