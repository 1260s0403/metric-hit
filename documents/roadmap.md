# Roadmap MetricHit OS

## Завершено

- защищённая память и экспорт current context;
- рекомендации Артёма и идеи владельца;
- преобразование knowledge → task;
- управление задачами;
- обзор;
- глобальный поиск;
- активность и audit;
- backup/restore infrastructure;
- проекты.
- минимальная repo-side запись/audit для `Strategy → native Codex task-thread → commit/result` через approved decision delta и существующий task-контур.
- миграция проекта «Ядро» на SERVER и проверки; SERVER является primary workspace, домашний ПК — резервной точкой.
- текущий MVP workflow: серверный Strategy — основной координационный чат, `native Strategy → один task-thread → commit/result`; после запуска Strategy сообщает имя executor-а и точный scope. Пока executor активен, Strategy удерживает work turn открытым и не выдаёт финальный ответ; допустим только явно помеченный in-progress комментарий. Финальный итог (готово/blocked, commit если есть, проверки, `git status`, blocker если есть) Strategy публикует только после результата и проверенного статуса либо при реальном blocker, без периодических статусов, scheduler, UI или новой функциональности. iPhone Remote к SERVER работает, подключение ноутбука запланировано на 17.08.2026; обычная разработка внутри `C:\MetricHit\workspace` использует локальный Codex в режиме Full access + Never ask и проходит без ручных approval prompts, при этом удаления, force-операции, изменения доступов, публикации, расходы, изменения стратегии, памяти или настроек и другие опасные действия по-прежнему требуют явного решения владельца; обычная разработка — GPT-5.6 Terra Medium, Sol/Luna — только по policy. Dispatcher и SDK не обязательны и не развиваются без доказанной необходимости.
- unified intake v1: текст, ссылки и текстовые файлы. Голос не является отдельным входящим контуром MVP: диктовка выполняется средствами устройства или браузера, а в «Ядро» поступает уже текст; аудио не принимается, не транскрибируется и не хранится.
- UI управления памятью: список и подробности pending-кандидатов, защищённые подтверждение и отклонение, явное разрешение конфликтов с обязательной причиной и сохранением audit/history.
- HTML, CSS и vanilla JavaScript операторской панели отделены от Python/FastAPI; новый frontend-стек и зависимости не добавлены.
- короткий UX-проход обзора владельца: приоритеты дня, ожидающие решения, ближайшие задачи и недавняя активность, с разделением глобальной и локальной навигации.
- project scope MVP: «Ядро» — самостоятельная инфраструктура/control plane; «Развитие Ядра» — внутренний независимый проект, MetricHit — первый независимый бизнес-проект. Поддерживается один уровень принадлежащих проекту подпроектов; новые задачи, рекомендации и идеи обязательно scoped с default MetricHit, legacy-записи не переназначены.

## Следующие этапы

1. Минимальный контракт автономного отдела.
2. Подготовка редакции как первого автономного отдела.

Направления дальнейшего развития: цели и измеримые результаты, реестр решений, гипотезы и эксперименты, центр решений владельца, простая экономика проектов и отделов, ежедневные и недельные сводки, объяснимое состояние проектов и отделов и повторно используемые шаблоны запуска. Это направления, а не реализованные функции.

## На паузе до решения владельца

- editorial OpenAI API;
- автоматические публикации;
- production-развитие редакции.

Сложный Гант, корпоративный чат, видеосвязь, тяжёлый календарь и замена CRM не входят в текущий приоритет.
