# Политика выбора модели Codex

- Исходное решение: 13.08.2026; дополнено владельцем 15.08.2026, 16.08.2026 и 26.08.2026.
- Источник: прямое подтверждение владельца MetricHit.

## Модель по умолчанию

Стандартные задачи выполняются внутренним executor на GPT-5.6 Terra с reasoning Medium. Fast-path задачи автоматически направляются на самую быструю доступную совместимую одобренную модель без отдельного вопроса владельцу. Если она недоступна, executor без остановки использует Terra Medium. Эта маршрутизация применяется только к внутреннему executor там, где платформа поддерживает выбор модели, и не меняет owner-visible Strategy-модель.

## Переключение для специальных задач

- Самая быстрая доступная совместимая одобренная модель используется для небольших изолированных UI-правок, CSS, текстов интерфейса, узких исправлений, docs и коротких тестовых циклов.
- Spark не используется для архитектуры, SQLite-схем, бизнес-логики, авторизации, security, backup/restore, миграций и больших сквозных модулей.
- Перед сложной архитектурной, security-критичной или особо ответственной задачей Codex предлагает владельцу GPT-5.6 Sol и ждёт явного подтверждения переключения.
- Перед массовой классификацией, извлечением, обработкой большого количества однотипных материалов или фоновыми операциями Codex предлагает GPT-5.6 Luna и ждёт явного подтверждения переключения.
- После завершения специальной задачи Codex предлагает вернуться к GPT-5.6 Terra с reasoning Medium.

Sol и Luna не назначаются без явного подтверждения владельца. Автоматический выбор обычной fast-path модели внутри executor и fallback на Terra Medium подтверждения не требуют.

## Жизненный цикл выбора модели

- Перед каждой новой задачей модель классифицируется заново.
- Разрешение на Sol или Luna действительно только для конкретной задачи либо явно непрерывного этапа и не переносится автоматически на следующую задачу.
- Недоступность предпочтительной fast-path модели не блокирует задачу: используется Terra Medium.
- Требуемая модель определяется отдельно для каждой задачи. Сразу после запуска автоматически созданный engineering task-thread обязан сверить свою фактическую модель с требуемой для этой задачи.
- Если задача требует Sol или Luna, а task-thread запущен на другой модели, он до любых критических действий останавливается и просит владельца переключить модель. Обычный fast-path mismatch не блокирует работу.
- После переключения task-thread продолжает с текущего состояния: без отката, создания нового thread или перезапуска задачи.
