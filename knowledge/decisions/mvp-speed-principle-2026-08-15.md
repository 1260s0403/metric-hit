# Принцип MVP и скорости разработки

- Решение владельца: 15.08.2026.
- Источник: прямое подтверждение владельца MetricHit.

Скорость разработки критична. Для каждой задачи реализуется минимальный законченный пользовательский сценарий. Нельзя добавлять функции и абстракции «на будущее»; сложность допустима только при доказанной необходимости. Большие задачи по возможности делятся на законченные вертикальные этапы примерно по 20–30 минут, но не так, чтобы система оставалась небезопасной, полурабочей или неконсистентной. Нельзя экономить на целостности данных, security, idempotency, критических тестах и восстановимости. Недоделанное не считается MVP.
