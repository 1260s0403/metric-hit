# Передача автоматизации Freelance.ru в основной проект

Дата подготовки: 2 сентября 2026 года.

Этот документ описывает только работу с Freelance.ru: создание, публикацию и учёт карточек услуг. Упоминания и материалы, не относящиеся к Freelance.ru, намеренно исключены.

## Итог текущего состояния

Готов локальный конвейер на Node.js + Playwright. Он делает следующее:

1. Берёт каталог уникальных услуг из `data/offers.json`.
2. Валидирует данные и собирает очередь в `outputs/publish-queue.json`.
3. По прямой команде владельца запускает обычный установленный Google Chrome с локально сохранённой DPAPI-шифрованной сессией Freelance.ru.
4. Заполняет форму услуги: категорию, название, цену, срок, описание, ключевые слова.
5. Загружает обложку из локального файла и выбирает её как обложку услуги.
6. При запуске с `--submit` создаёт карточку на Freelance.ru и сохраняет полученную публичную ссылку в очереди.
7. Не отправляет на публикацию карточки, уже отмеченные как `published`.

Выполнена проверка после ошибки с повторным SEO-объявлением: опубликованные карточки не возвращаются в очередь после её пересборки. Тест проходит командой `npm test`.

Файл сессии не переносится и не хранится в проекте. При повторной авторизации по прямой команде владельца сценарий сохраняет состояние только здесь:

```text
C:\ProgramData\MetricHit\automation-secrets\freelance-ru\freelance-session.dpapi
```

Файл защищён Windows DPAPI для текущей учётной записи и ACL только для текущей учётной записи, SYSTEM и локальных администраторов. Пароль не сохраняется. Если сессия перестала работать, не редактируйте файлы вручную: запустите `npm run reauth` только после прямой команды владельца, войдите в открывшемся Chrome и нажмите Enter в терминале.

```text
│  ├─ publish-queue.json
│  └─ offer-catalog.md
├─ package.json
└─ .gitignore
```

В PowerShell из корня основного проекта:

```powershell
npm install
npm test
npm run build:queue
```

Скрипты используют Node.js в ESM-режиме (`"type": "module"` в `package.json`) и зависимость `playwright`.

Используется установленный обычный Chrome, а не отдельный браузер Playwright:

```js
chromium.launch({ channel: "chrome", headless: false })
```

Это важно: при первоначальной настройке отсутствовал встроенный браузер Playwright. Проблема была устранена установкой браузерного пакета, а затем скрипты были переведены на запуск обычного Chrome через `channel: "chrome"`.

## Рабочие команды

### Проверка и сбор очереди

```powershell
npm run build:queue
```

Проверяет:

- уникальность пары «категория + название»;
- допустимость категории;
- длину названия и описания;
- положительные целые цену и срок;
- наличие ключевых слов.

Результаты записываются в:

- `outputs/publish-queue.json` — машиночитаемая очередь;
- `outputs/offer-catalog.md` — компактная таблица для просмотра.

### Регрессионная проверка

```powershell
npm test
```

Тест подтверждает, что SEO-карточка с ID `seo-starter`, уже опубликованная под №102062, сохраняет статус `published` и свою ссылку после пересборки очереди.

### Сохранение/обновление сессии

```powershell
node scripts/save-freelance-session.mjs --owner-command
```

Или двойным кликом:

```text
outputs\save-freelance-session.cmd
```

### Подготовка новых карточек без публикации

```powershell
npm run publish -- --limit=1
```

Без `--submit` скрипт проходит заполнение и помечает карточки как `prepared`; новых объявлений на сайте не создаёт.

### Публикация новых карточек

```powershell
npm run publish -- --submit --limit=1
```

`--limit=1` — безопасный режим: публикуется только первая карточка со статусом `ready`. После успешной публикации записываются `status: "published"`, `publishedUrl` и `publishedAt`.

### Удаление подтверждённого исторического дубля

```powershell
npm run delete-duplicate
```

Эта команда намеренно ограничена только старым дублем №102063. Для удаления других услуг нужно сначала изменить скрипт и добавить отдельную проверку ID, названия и ссылки. Не превращайте её в массовое удаление.

## Как добавлять новую уникальную услугу

1. Добавить объект в `data/offers.json`.
2. Указать уникальный `id`, категорию, название, `priceRub`, `deliveryDays`, `keywords`, `description` и путь к обложке.
3. Для новой услуги **не указывать** `status` и `publishedUrl`: тогда при сборке она получит статус `ready`.
4. Положить обложку в `outputs/covers/` и указать путь, например `outputs/covers/new-service.png`.
5. Выполнить `npm run build:queue` и убедиться, что в очереди только ожидаемые новые позиции.
6. Публиковать небольшими группами, начиная с `--limit=1`.
7. После каждой публикации проверить сохранённые публичные URL и журнал.

Пример объекта:

```json
{
  "id": "unique-service-id",
  "category": "Веб-разработка и IT",
  "title": "Уникальное название услуги",
  "priceRub": 30000,
  "deliveryDays": 7,
  "keywords": ["ключ 1", "ключ 2"],
  "description": "Полное описание объёма работ, результата, ограничений и того, что предоставляет заказчик.",
  "cover": "outputs/covers/unique-service.png"
}
```

## Важные ограничения Freelance.ru

На странице создания услуги платформа предупреждает, что множественная публикация аналогичных/однотипных услуг запрещена и может привести к блокировке учётной записи. Поэтому конвейер следует использовать только для действительно разных, содержательно самостоятельных услуг. Массовая генерация 100–200 похожих карточек не должна быть автоматизирована.

Автоматизация не обходит CAPTCHA, не использует и не хранит пароль. Авторизация выполняется в браузере по прямой команде владельца, а затем применяется только локальная DPAPI-шифрованная сессия вне проекта. Расписания нет; публикация, редактирование или удаление выполняются лишь после прямой команды владельца и без отдельного подтверждения каждой позиции.
