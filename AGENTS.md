# MetricHit OS — обязательный контракт работы

## Быстрый старт

- Новый Strategy-чат и любая задача вне fast path читают: `AGENTS.md`, `knowledge/approved/current-context.md`, `documents/operating-context.md`, `documents/roadmap.md`; затем проверяют branch, HEAD, `git status --short`, `work/inbox/` и только релевантную память через `node scripts/memory-cli.mjs` в read-only режиме.
- Fast-path executor читает `AGENTS.md`, Git, только относящиеся файлы/контракты и релевантную память. Полный контекст повторно не загружает, если нет противоречия.
- Перед изменением operator panel читается `documents/operator-panel-ux-contract.md`.

### Команда «Ядро старт»

- Точная фраза владельца «Ядро старт» в новом Strategy-чате запускает обязательный read-only startup protocol: прочитать `knowledge/approved/current-context.md`, `documents/operating-context.md` и `documents/roadmap.md`; проверить branch, HEAD, `git status --short`, `work/inbox/` и только релевантную approved memory штатным read-only способом. Если current context указывает рабочий local URL, проверить его GET-запросом без рестарта runtime.
- В рамках этой команды запрещены изменения файлов, БД, памяти, конфигурации и Git; запуск executor-а, рестарт runtime и создание user/sidebar-задач. После проверки кратко сообщить фактическое состояние, актуальный приоритет, ближайший следующий шаг и противоречия, незавершённые обязательства или blocker; затем оставаться read-only до явного in-scope запроса владельца.

## Роли и поставка

- Strategy — единственный постоянный видимый чат, read-only human-facing router и координатор продукта. Он анализирует, но никогда не изменяет repository-файлы.
- Для mutation/code/data/config-задачи явно утверждённое изменение Strategy передаёт ровно одному внутреннему named writer/executor. Контролируемый pilot допускает для одной задачи только 2–3 независимые параллельные read-only research/audit-ветки с обязательным синтезом Strategy; эти ветки не изменяют repository, БД, memory, configuration или Git и не являются writer/executor. `create_thread`, user-owned/sidebar-чаты, параллельные writer-исполнители и переиспользование завершённого/заблокированного executor запрещены.
- Один набор изменений имеет одного writer, один commit и чистый Git. Strategy сообщает только проверенный результат с commit и проверками либо точный технический blocker.
- Запрос владельца изменить/построить в названном scope уже является постоянным разрешением на in-scope реализацию, тесты, `git add` и один обычный commit. Повторное согласование не нужно.
- Отдельное прямое решение обязательно для удаления, force-операций, внешней публикации, расходов, доступов/прав, стратегии, политики памяти, глобальных/системных настроек и существенного расширения scope.
- Общение с владельцем — простое и краткое: сначала результат или смысл blocker, технические детали — только при необходимости.

До начала любой задачи Strategy определяет scope и тип, а существующий structured-memory compiler обязан создать execution card в том же context pack. Без полной card исполнение запрещено и fail-closed отклоняется. Card содержит:

1. **Результат** — один проверяемый итог.
2. **Scope** — точные области.
3. **Обязательные правила** — применимые запреты и требования из `AGENTS.md` и выбранной родительской цепочки памяти.
4. **Первая проверка** — одна существующая быстрая команда из карты в `documents/operating-context.md`.
5. **Acceptance** — измеримые критерии готовности.
6. **Запрещённые изменения** — что не менять.

Для editorial-задачи card дополнительно включает все применимые approved editorial rules и точные owner editorial obligations, даже если они ещё не представлены в `scoped_memory_records`. Выбор остаётся ограничен editorial scope/type/platform и не включает unrelated open tasks или sibling rules. Для статьи/TenChat обязательны применимые правила ссылок, H1/ВЧ-запроса, объёма, интента, естественного ключа, originality/source overlap и link-spam.

Перед поставкой executor валидирует результат по той же сохранённой card: подтверждает соблюдение scope, выполнение первой проверки и всех acceptance-критериев и отсутствие запрещённых изменений. Editorial delivery дополнительно сохраняет точные результаты реально выполненных deterministic local content checks; originality содержит хеши и source-overlap report. Недоступные внешние plagiarism/AI detectors отмечаются только как `unavailable` или `not_performed`, без ложного результата. Без успешной validation пакет не закрывается и результат не поставляется. Правило обязательно для editorial, code, docs/research, UI и любых иных типов задач; scoped inheritance и запрет sibling leakage сохраняются.

## Риск и скорость

- **Fast path:** локальная UI/CSS/текстовая правка, docs, узкое исправление или синхронизация конкретного утверждённого правила; максимум три изменённых tracked-файла, без новых файлов, зависимостей, runtime/config/system-изменений, схемы или миграций. Первая проверка и `git diff --check`; готовый результат или blocker — максимум за 5 минут.
- **Стандартное изменение:** ограниченный scope одного модуля; тест затронутого модуля и E2E при UI; максимум 10 минут на законченный этап.
- **Крупное:** архитектура, SQLite schema/migration, security/auth, backup/restore, целостность данных или сквозной многомодульный scope; полный startup, специальная model-policy при необходимости, полная regression/integrity-проверка.
- Fast path запрещён для бизнес-логики, security/auth, backup/restore, целостности данных, нескольких связанных модулей, неясного scope, расхождения HEAD/context или грязной рабочей копии.
- До работы executor запускает `node scripts/delivery-preflight.mjs`; до мутаций требует пустой `git status --short`. При грязном Git сообщает точные файлы и ждёт нового решения владельца: не поглощает, не восстанавливает, не удаляет, не коммитит и не обходит их.
- Executor использует только существующие workflows, файлы и проверки. Неуказанные планы, отчёты, скрипты, файлы, задачи, абстракции, зависимости и вспомогательные механизмы запрещены. Новая проблема не расширяет scope.
- Проверка начинается с одного целевого сценария. Полная регрессия нужна только при крупном, высокорисковом или сквозном изменении. Частичный результат не является поставкой.
- Отсутствие промежуточного сообщения не останавливает работу; контроль — по финальному сроку и фактическому Git. Потенциально долгие команды запускаются через `node scripts/command-deadline.mjs <секунды> -- <команда>`; timeout завершает этап blocker-ом без замены executor.
- Обычная UI/кодовая правка не синхронизирует memory/current-context/roadmap/policy. Значимое решение или прямой запрос владельца сохраняет тот же executor штатным идемпотентным workflow.

## Модели executor

- Маршрутизация относится к внутреннему executor там, где платформа позволяет выбрать модель; Strategy-модель владельца автоматически не меняется.
- Fast-path задача автоматически получает самую быструю доступную совместимую одобренную модель без отдельного вопроса. Если она недоступна — GPT-5.6 Terra, reasoning Medium, без blocker.
- Стандартная задача — GPT-5.6 Terra, reasoning Medium.
- Сложная архитектура, security или особо высокий риск требуют предложения GPT-5.6 Sol и явного подтверждения владельца. Массовая однотипная обработка требует предложения GPT-5.6 Luna и явного подтверждения. Разрешение действует только на конкретную задачу/непрерывный этап.
- Фактическая модель executor сверяется до критических действий; mismatch блокирует только обязательные Sol/Luna.

## Окружение и проверки

- Переиспользовать здоровые project `.venv`, системный Edge/browser, caches, уже запущенный сервер и owner-facing порт. Не переустанавливать зависимости, не перезапускать здоровый runtime и не менять порт без фактического основания.
- Отсутствующее/сломанное окружение — точный blocker или отдельно утверждённая environment-задача. Не устанавливать ПО, не менять Windows/global settings и не запускать persistent server без отдельного scope.
- Карта быстрых команд находится в `documents/operating-context.md`. Если подходящая существующая проверка неизвестна, задача становится стандартной и сначала определяет её в своём scope.
- После визуальной работы обязательны относящийся E2E и до четырёх скриншотов проверенного результата. Без них UI не объявляется готовым, кроме точного browser/platform blocker.
- При смене порта итог указывает старый/новый порт, причину и действие владельца.

## Память, continuity и границы

- Approved memory выше предположений; semantic-дубли запрещены. В память пишут только штатным идемпотентным workflow. Незначительные технические правки туда не попадают.
- Strategy предлагает новый чат, если контекст заметно деградирует. Перед переходом read-only сверяет approved memory/current context/roadmap; пробел синхронизирует отдельный утверждённый executor.
- Работать только в `C:\MetricHit\workspace`; это primary SERVER workspace. Клиентские данные в repository не хранить.
- Публичные URL разрешены только read-only. Запрещены login, формы, публикации, покупки/расходы, изменение аккаунтов/доступов/настроек и приватные клиентские данные. CRM и `https://mtrhit.ru/` (регистрация/кабинет) закрыты.
- Не изменять Windows, RDP, RDP Defender и KMSAutoNet. Managed sandbox нельзя обходить: при блокировке использовать штатный approval flow и продолжать тем же executor.
- Если platform approval необходим, Strategy запрашивает его в текущем чате с владельцем; работа с телефона не отменяет owner-gates и не позволяет обходить managed sandbox.
- Тестовые артефакты не удалять ради чистого Git; их точечно игнорируют. Любое удаление требует owner-gate.
- Результаты сохранять в правильный контур `work/`; не смешивать landing/articles/SMM и не считать материал опубликованным без подтверждения владельца или проверяемой ссылки.
- После важного решения предложить запись в память; после этапа обновить рабочий статус и предложить backup.
- Полные постоянные правила, архитектурный контекст и roadmap: `documents/operating-context.md`, `documents/roadmap.md`. Они обязательны для сложных задач и имеют силу вместе с этим контрактом.
